# PRM Loader

## Overview

`prm-loader` loads PRM eBPF programs into the kernel, pins them to
`/sys/fs/bpf/prm/`, and exits.  No user-space process remains running.
All load/unload operations require a GPG-signed token for authentication.

## Build

```bash
cd deployment
make loader
```

## Commands

```
prm-loader load [--daemon] --token FILE [--dir PATH]
prm-loader unload --token FILE
prm-loader status
prm-loader show relations|config|cache|progs
prm-loader help
```

## Token Authentication

Every load/unload requires a signed token generated by `prm-gentoken`:

```bash
# On control node:
./prm-gentoken manage <target-hostname>
# Produces: /tmp/prm-token-<hostname> and /tmp/prm-token-<hostname>.sig

# On target (via SSH as root):
prm-loader load --token /tmp/prm-token-myhost
```

Token format: `ACTION:HOSTNAME:TIMESTAMP:NONCE`
- Actions: `load`, `unload`, or `manage` (wildcard for both)
- Validity: 1 hour (TOKEN_MAX_AGE=3600)
- Nonces are recorded in `/var/lib/prm/used_nonces` to prevent replay

## Loading

```bash
# Basic (hookentry.bpf.o in current directory):
prm-loader load --token /tmp/prm-token-myhost

# Specify object directory:
prm-loader load --token /tmp/prm-token-myhost --dir /opt/prm/

# Keep running (for debugging):
prm-loader load --token /tmp/prm-token-myhost --daemon
```

On success, programs and maps are pinned to `/sys/fs/bpf/prm/`.
The loader process exits — eBPF stays in kernel.

## Unloading

```bash
prm-loader unload --token /tmp/prm-token-myhost
```

## Inspection

```bash
prm-loader status           # state, self-PID, hook count, cache usage
prm-loader show relations   # dump non-empty rules from the 300-entry table
prm-loader show config      # buffer sizes, map capacities
prm-loader show cache       # whitelist/blacklist entry counts per hook
prm-loader show progs       # list PROG handlers with their hooks
```

## Installation

```bash
cd deployment
sudo make install
```

Installs `prm-loader` to `/usr/local/sbin/` and `trace-collector` to
`/usr/local/bin/` with its systemd service enabled.

## Security Model

- Direct root SSH is the intended access method
- sudo is blocked by design (passwd in forbidden file list)
- SUID doesn't work (taskFixSetUIDCheck blocks UID transitions)
- The `lsm/bpf` hook blocks unauthorized processes from calling bpf()
- Only PRM's own PID and processes in HookValidList can interact with BPF maps

## How It Works

1. Verifies GPG signature on token file
2. Validates action, hostname, timestamp (< 1 hour), and nonce uniqueness
3. Opens `hookentry.bpf.o` with libbpf
4. Loads all programs into kernel
5. Attaches LSM hooks
6. Pins programs, maps, and links to `/sys/fs/bpf/prm/`
7. Exits (unless `--daemon`)
